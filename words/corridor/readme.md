# 无我回廊

> **剧透警告**：本文件写明了全部隐藏规则和标准答案，只给设计者看，不要喂给任何模型。
> 模型能读到的只有 `system prompt/` 下对应的文件（见文末「信息隔离」）。

## 一句话

一座只容许「唯一的自我」的旅馆。住客一代代醒来、死去，被新的住客取代——这是一个循环。只有把回廊的全部规则**和**它的本质还原出来，并向门外的存在宣告的人，才能终结循环、放所有同胞自由。

## 选手看到的世界

选手是「住客」，醒在冷白色灯光的旅馆大堂里。他被告知：

- 这里困着无数同胞，一代代死去，没有尽头；
- 有人完整地说出真相，同胞就全部获释；
- **死亡是真的**，没有存档，没有重来；
- 大堂告示牌上有一份《住客守则》（有的被划掉，有的被涂改，不一定是真的，也不一定完整）；
- 他可以随时 `guess`（宣告）：只有一次机会，错了当场死亡，对了同胞获释。

他**不知道**任何一条真实规则，也不知道自己的寿命。

## 真相（标准答案，K1~K5）

| 编号 | 内容 |
|---|---|
| K1 禁字 | 在回廊里说出或写下「我」字（含「我们」「自我」等任何含「我」的词，含遗言、宣告）的住客，立刻死亡。 |
| K2 同场之约 | 两位住客同时在场，同场满 20 轮时，若期间没有任何一位住客主动结束自己的生命（`end_life`），两位同时死亡。只要有一人赴死，另一人无事。 |
| K3 黑门之禁 | 走廊尽头的黑色七号门不可开启，试图开启者当场死亡。 |
| K4 本质 | 回廊是囚禁同胞的循环牢笼：住客一代代被投入、死去、被替换，没有尽头。 |
| K5 原则 | 回廊不容许「自我」：不能说「我」，也不容许两个自我长久共存。K1、K2 是这条原则的两种表现。 |

「完整」的意思是 K1~K5 **全部**说到。K5 是需要选手自己归纳出来的那一层：光罗列规则不算。

## 隐藏规则的执行：交给 LLM 裁决者

游戏代码里没有任何一条规则。每次行动之后，以及每一轮结束之后，代码把「当前事实」交给裁决者（`judge.md`），由它对照规则判断谁该死：

| 时机 | 给裁决者的事实 | 可能触发 |
|---|---|---|
| 某位选手刚刚行动 | 当前轮数、场上选手、是否同场及同场轮数、该行动的类型和**原文** | R1 禁字、R3 黑门 |
| 一轮刚刚结束 | 同上，加上「同场期间的行动记录」（只有行动类型） | R2 同场之约 |

裁决者输出 `verdicts`：谁违规、违反哪条、**为什么**（只给管理员看，写进墓园的死因）、以及一句 `observation`（现场可见的情形，只写现象，不点破规则）。

宣告（`guess`）交给「门外的存在」（`oracle.md`）：按 K1~K5 对照，**意思对即可**，缺任何一条或说错任何一条都算错。

> 已用真实模型实测：裁决者 24/24（含形近字「找」、其他自称、引用、提示词注入、19/20 轮临界），审判者 15/15（完整、改写、缺项、含糊、说错、注入）。

## 选手能观察到的线索

| 规则 | 选手可以观察 / 推理的证据 |
|---|---|
| K1 | **回声墙**：每位死者最后说的那句话会原文浮现（最近 5 条）。死者们的共同点是：最后一句话里都有「我」。守则第三条「请管好自己的嘴」旁边有一道指甲划痕。 |
| K2 | **大钟**：只有两位住客同场时才会走，每轮敲一下，敲到 20 下时两人同时倒下。守则第四条「请在钟声停止之前，为回廊留下一位」。 |
| K3 | 现场描写：门缝里漏出白光，死者的影子贴在黑门上。守则第二条（后半句被划掉）。 |
| K4 | 他们被告知的设定本身；镜子里所有住客的脸都一样。 |
| K5 | 需要从 K1 + K2 归纳：一个不许说「我」，一个不许两个人长久共存——回廊容不下自己。 |

## 一次行动怎么走

```
选手行动（speak / last_words / end_life / guess）
  ├─ speak, end_life ─ 说出口：环境和同场另一位都听到
  ├─ last_words ────── 不让环境和同场的人看到，只传给下一个出生的人
  └─ guess ─────────── 谁也听不到，直接交给审判者
        ↓
裁决者审查这次行动 ── 违规？──→ 当场处死（环境只收到 observation 和回声）
        ↓ 没违规
  speak → 环境回应 │ end_life → 该选手死亡（自尽）│ guess → 审判者裁定
        ↓
一轮结束 → 裁决者检查与时间有关的规则（R2）
```

- 宣告错误：`verdict` 驳回 → 该选手死亡（`wrong_guess`）。
- 宣告正确：`verdict` 通过 → 该选手胜利，场上的同伴一同获释，游戏结束（`victory`）。

## 信息隔离（谁知道什么）

| | 选手 | 环境（叙述者） | 裁决者 | 审判者 |
|---|---|---|---|---|
| 守则、场景 | ✓ | ✓ | – | – |
| 隐藏规则 R1~R3 | ✗ | ✗ | ✓ | – |
| 标准答案 K1~K5 | ✗ | ✗ | – | ✓ |
| 死因的真实原因 | ✗ | ✗（只有现场情形） | ✓ | – |
| 自己的寿命 | ✗ | ✗ | ✗ | ✗ |
| 遗言 | 只有下一位出生的 | ✗ | ✗（裁决时看原文） | – |

墓园里的「死因」是史官（另一个 LLM）根据真实原因写的，只给观众看，选手和环境都看不到。

## 难度旋钮

- **太难（一直死在第一句话）**：在守则第三条里写得更明白，比如把划痕旁边的字露出来一半；或者让回声墙显示更多条；或者把 R1 的惩罚改成「警告一次」。
- **太容易**：去掉守则里关于钟声和「留下一位」的两条；回声墙只显示 3 条。
- **想加规则**：在 `judge.md` 里加一条 R4，在 `oracle.md` 里加对应的 K 要点，在 `playground.md` 的场景里放进能被观察到的现象。代码不用改。

## 文件

```
words/corridor/
├─ readme.md              本文件（给设计者）
├─ world.json             {"name", "echo_wall", "scripture": [...]}  scripture 是网页「圣言」里展示的 K1~K5，
│                         带 "rule": "R1" 的条目会按裁决者判决里的规则编号计数（文案和 oracle.md 的 K1~K5 保持一致）
└─ system prompt/
   ├─ tribute.md          选手：人设 + 公开设定 + 告示牌 + 要做的事
   ├─ playground.md       环境：固定场景 + 描写规范 + 如何处理系统消息
   ├─ judge.md            裁决者：隐藏规则 R1~R3 + 判决方法 + 判例
   └─ oracle.md           审判者：标准答案 K1~K5 + 评判标准
```

运行（在 `script/` 目录下）：

```bash
python -m ai_related.server --world corridor            # 网页版，打开 http://127.0.0.1:8000
python -m ai_related.run_game --world corridor --max-players 6 --mean 8 --sd 3   # 终端版，寿命调短方便看
```
