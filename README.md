# AI 饥饿秀

一个「环境」AI 和一代又一代短命选手 AI 的对话秀。选手死后，下一位选手接班，并且只能看到上一位留下的遗言。

## 运行

在 conda 环境 `hunger_show` 里（`pip install -r script/ai_related/requirements.txt`），key 写在 `script/ai_related/.env` 的 `DEEPSEEK=` 里。

```bash
cd script
python -m ai_related.server              # 然后打开 http://127.0.0.1:8000
python -m ai_related.run_game --max-players 2 --mean 4 --sd 1   # 不开网页，在终端里跑（寿命调短方便测试）
```

不起后端也能看界面：直接双击 `web/index.html`，会播放一段演示数据（右上角标签显示 `DEMO`）。

服务端常用参数：`--budget 1.0`（估算费用到这个数就停，美元）、`--delay 2.0`（每轮间隔秒数）、`--no-autostart`（先不开始，`POST /api/start` 再开始）、`--max-players N`、`--data-dir logs/game`。
**默认会一直跑到花满预算为止**，别忘了设 `--budget`。

## 游戏规则（`script/ai_related/game.py`）

1. **寿命**：每位选手入场时随机一个**隐藏**寿命，2~80 次行动的截断正态分布（均值 41、标准差 15，见 `config.py`），寿命一到立刻死亡。**选手不知道这个范围**，也不知道自己还剩多久。
2. **轮数**：世界按「轮」计时，每一轮场上每位选手各行动一次。轮到选手时，会告诉他现在是**世界的第几轮**（绝对轮数，两位同场选手看到的是同一个数字）。新出生的选手从下一轮开始行动。
3. **同场人数**：最多同时两位，开局一位。有人死亡时：原来场上有两位 → 25% 补一位新选手；原来只有这一位 → 90% 补一位，10% 一次补两位。场上不会空。两位选手在同一个场景里，看得到彼此的发言和环境的回应；死亡是公开的（对方会收到"某某死亡了"），但遗言不是。
4. **遗言**：每次行动二选一：`speak`（说话/做事，环境会回应）或 `last_words`（花掉这一整次行动留遗言，只能留一次）。遗言**环境看不到、同场的另一位也看不到**，不影响世界；只有**下一个出生的选手**能看到（"下一个"指最近一次死亡的那位留下的；两位同时出生时两位都能看到），并且知道这是前人留的。没来得及留遗言就死了，后来者什么也收不到。
5. **名字**：每位选手入场时自己取名字（不能和已有的、在世的重名）。
6. **墓园**：选手死亡时，由 LLM 生成死因和人物生平，写入墓园（`data-dir/graveyard.json`）。点网页上的「墓园」按钮查看：石碑 = 留下了遗言，木十字架 = 没来得及留；点开某一条看入场/死亡的轮数、生平和遗言。

网页上，**遗言轮**是墓碑形的灰色气泡（两侧烛光、字一个一个慢慢刻出来、头像像幽灵一样飘），**死亡轮**是红黑色的死亡框（骷髅、缺角红框、出现时震一下，点一下打开这个人的生平）。

选手和环境的性格写在 `words/example/system prompt/tribute.md`（选手）和 `playground.md`（环境）里，规则部分由代码追加，不用写在文件里。文件内容太短（<30 字）时用内置默认 prompt。

## 目录

```
script/ai_related/   Python 后端：LLM 调用（insert_context / compress_context / get_reply / get_json_reply）、游戏、服务
web/                 前端（8-bit 像素风，纯静态，无需构建），见 web/README.md
words/               system prompt
```

数据（墓园、对话记录）默认存在 `script/logs/game/`，已被 `.gitignore` 忽略。
